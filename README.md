# Вы можете просмотреть предыдущие сессии несколькими способами:
****************************************************************
  1. Через команды в терминале (до запуска CLI)
   * gemini --list-sessions — выводит список всех доступных сессий для текущего проекта с их ID, названиями и временем.
   * gemini --resume [index|ID] — позволяет продолжить конкретную сессию по её индексу или ID.

  2. Внутри интерактивного режима
   * Введите команду /resume (или /chat). Это откроет Session Browser, где можно прокручивать список прошлых сессий,
     искать их по содержимому и выбирать нужную для загрузки.
   * Нажмите F12, если вам нужно открыть панель отладки и посмотреть технические логи текущей сессии прямо в терминале.

  3. Где хранятся файлы
  На Windows история сессий сохраняется в формате JSON по пути:
  C:\Users\Hospes\.gemini\tmp\quadus\chats\

  (Где quadus — это хеш или имя вашего текущего проекта). Там вы можете найти полные логи диалогов, включая вызовы
  инструментов и ответы модели.

  4. Экспорт
  Если вы хотите сохранить текущую сессию в читаемом виде, используйте команду:
   * /chat share my_session.md — это экспортирует диалог в Markdown-файл.

# LogicManager::relaySwitch(uint8_t cn)
************************************* 
  отвечает за циклическое управление реле (обычно это полив) на
  основе таймеров. Она работает по принципу конечного автомата, переключая состояние реле между «Включено» и «Выключено»
  через заданные интервалы времени.

  Вот подробный разбор того, что происходит внутри:

  1. Выбор параметров канала
  Функция принимает номер канала cn (1, 2 или 3) и подгружает соответствующие ему данные:
   * Текущее состояние реле (RELAY1, RELAY2 или RELAY3).
   * Оставшееся время текущей фазы (pvTimeR1, pvTimeR2 или pvTimeR3).
   * Настройки длительности: время работы (spOn) и время паузы (spOff).
   * Режим работы (Permit): разрешающее условие (всегда, только при включенном свете или только при выключенном).

  2. Проверка условий (Mode/Permit)
  Прежде чем считать время, функция проверяет, разрешено ли реле работать в данный момент:
   * Если в настройках указано «работать только со светом», а свет выключен — реле принудительно выключается.
   * Если условия не соблюдены (permit != 0), таймер сбрасывается в -1, а реле переходит в состояние PCF_OFF.

  3. Логика таймера (циклическое переключение)
  Если работа разрешена (permit == 0), выполняется основной алгоритм:
   1. Уменьшение счетчика: Каждую минуту (так как функция вызывается в main.cpp раз в минуту) значение таймера val
      уменьшается на 1.
   2. Переключение при val <= 0: Когда время вышло, происходит смена фазы:
       * Если реле было ВЫКЛЮЧЕНО: оно включается (PCF_ON), а таймеру присваивается значение spOn (длительность полива в
         минутах).
       * Если реле было ВКЛЮЧЕНО: оно выключается (PCF_OFF), а таймеру присваивается значение паузы, полученное через
         функцию transformTimeOff(spOff).

  4. Трансформация времени паузы (transformTimeOff)
  Поскольку время паузы может быть очень долгим (часы или дни), используется вспомогательная функция. Она преобразует
  индекс настройки в реальные минуты:
   * Значения до 10 интерпретируются как часы (например, индекс 5 превращается в 6 часов = 360 минут).
   * Значения 10 и выше интерпретируются как дни (например, индекс 10 — это 2 дня).

  5. Обновление состояния оборудования
  В конце функции новое состояние (ВКЛ/ВЫКЛ) и обновленное значение таймера сохраняются в глобальные переменные
  (sysState). Эти изменения затем передаются на аппаратный расширитель портов (PCF8574), который физически управляет
  контактами реле.

  Резюме: Эта функция реализует «умный» циклический таймер, который умеет подстраиваться под режим освещения и позволяет
  задавать паузы между поливами от нескольких минут до нескольких суток.

 Резюме для отладки:
   * Если хотите, чтобы насос поливал вместе с освещением — ставьте 1.
   * Если хотите, чтобы насос работал только ночью (в противофазе) — ставьте 2.
   * Если хотите, чтобы ему было все равно на свет — ставьте 0.

  И помните: в этом коде 0 — это когда всё работает, а 1 — когда всё отдыхает.

   1. Очистка кода: Из include/main.h полностью удален устаревший флаг isManualOverride_m и соответствующий макрос.
   2. Обновление логики управления (src/LogicManager.cpp):
       * В методы processLighting, processIrrigation и processClimate внедрена проверка dataOut[i].
       * Если dataOut[i] == 1, реле принудительно включается (PCF_ON).
       * Если dataOut[i] == 0, реле принудительно выключается (PCF_OFF).
       * Если dataOut[i] == -1, выполняется стандартная автоматическая логика (по таймерам или датчикам).
   3. Исправление логики кнопок (src/keypad.cpp):
       * Приведены в соответствие физические состояния: теперь 0 в dataOut действительно означает выключение (установка
         бита в 1), а 1 — включение (сброс бита в 0).
   4. Обновление REST API (src/server.cpp):
       * Эндпоинт /get_relays теперь возвращает режимы relX_m (-1, 0, 1) и текущие физические состояния.
       * Эндпоинт /set_relay принимает новые числовые значения режимов.
       * Функция /reset_auto теперь сбрасывает все 6 каналов в режим -1 (Авто).
   5. Новый веб-интерфейс (data/switch.html):
       * Вместо чекбоксов теперь используются группы из 3-х радио-кнопок (АВТО, ВКЛ, ВИКЛ) для каждого устройства.
       * Добавлена цветовая индикация выбранного режима и отображение текущего физического состояния реле (обновляется
         каждые 5 секунд).

  Теперь вы можете, например, оставить освещение в автоматическом режиме, но при этом принудительно выключить
  нагреватель или включить полив, не нарушая работу остальных систем.

# [pio system prune] Найпростіший спосіб запустити цю команду у VS Code:
********************************************************
  Спосіб 1: Через спеціальний термінал PlatformIO (Рекомендовано)
   1. У лівій панелі VS Code натисніть на іконку PlatformIO (голова мурахи).
   2. У меню Quick Access знайдіть розділ Miscellaneous.
   3. Натисніть на пункт New Terminal.
   4. У вікні, що відкриється, введіть ту саму команду:

   1    pio system prune
     Тут вона спрацює, бо PlatformIO автоматично підвантажує потрібні шляхи для свого терміналу.

  Спосіб 2: Через панель команд
   1. Натисніть Ctrl + Shift + P.
   2. Введіть PlatformIO: Core CLI.
   3. Відкриється термінал, де команда pio буде доступна.

  Спосіб 3: Якщо дуже хочеться в звичайному PowerShell
  Вам потрібно вказати повний шлях до файлу. Зазвичай він знаходиться тут:

   1 ~/.platformio/penv/Scripts/pio system prune

  Порада: Якщо місця на диску достатньо, ці 109 МБ можна не чіпати. Це просто "рекомендація" від інструменту, яка не
  впливає на стабільність вашого коду.
